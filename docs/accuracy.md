# 准确性怎么保证

> 本文是**唯一数字来源**。其他文档引用指标时请写「见 docs/accuracy.md」，
> 不要各自抄数字——2026-11-09 排查发现 tech-design 与 demo-script 里
> 同一指标出现过 0.952 / 1.000 两个版本，且评测集条数已与文件不符。

## 一、三层分离：不同层用不同的保证手段

| 层 | 内容 | 保证手段 | 不依赖模型 |
|---|---|---|---|
| ① 确定性计算 | FINDRISC / China-PAR / PLCO2012 风险值 | 对齐原始论文公式；边界值、NaN、缺项都有用例；`sanitize()` 兜底 | ✅ |
| ② 抽取 | 口述病史 → 结构化 JSON | 人工标注评测集 + 每次改动跑回归 + 精确率优先 | ❌ 用模型，但有评测集 |
| ③ 判定 | 遗传模式、通知分诊 | 配对评测 + 校准 ECE + 置信度门槛 + 拒答 | ❌ 但可换后端对比 |
| ④ 展示 | 用户看到的结论 | 不确定就不显示；文案写「提示，不是诊断」；缺口用于追问 | ✅ |

**核心原则**：模型只做它不可替代的事（把口语变成结构）。一旦涉及判断，先问
「能不能用规则或可复算的方式做」，不能才交给模型，且必须给出置信度与拒答路径。

## 二、可复现的指标（每次评测自动留痕）

评测脚本会把 **commit + 模型 + 数据集 + 逐条结果** 写进 `docs/eval-results/`：

```bash
# 需要 llama-server 在 127.0.0.1:8080
node scripts/eval-extract.ts --file=data/eval/pedigree-eval.jsonl
```

### 三轮干净留出集的进步（每套都是全新措辞，只跑一次）

| 留出集 | 期间做了什么 | Precision | Recall | F1 |
|---|---|---|---|---|
| v2 | 规则修补 + 词表初补 | 0.962 | 0.806 | 0.877 |
| v3 | 词表系统补齐（缺口清单） | 0.958 | 0.793 | 0.868 |
| **v5** | **规则抽取兜底 + 补充别名** | **1.000** | **0.839** | **0.912** |

**关键改动：规则抽取兜底**（`repair.ruleExtract`）。v4 显示 Precision 已 1.000、Recall 只有 0.750，
漏的几乎都是「词表能看见但模型认为不是病所以返回空」（甲状腺结节/骨质疏松/心脏不好/做支架）。
现在模型返回空时，用规则直接从原文抽（要求：有称谓、病名就近归属、前面 6 字无否定），
Recall 0.750 → 0.839，Precision 保持 1.000。

### holdout-v5 剩余 5 条（下一轮目标，不在本轮修）

| 例 | 现象 | 推断 |
|---|---|---|
| 「家里说我爷爷心脏放过支架」 | 漏抽 | 「放过支架」变体未收录 |
| 「我哥血压有点高」 | 漏抽 | 「血压有点高」不是别名 |
| 「外婆骨质疏松，我妈也是」 | 妈妈漏抽 | 续句补全用的是规范标签「其他」，补出病句 |
| 「我叔是不是糖尿病？」 | 漏抽 | 疑问句式在规则兜底里被 splitSegments 处理掉了 |
| 「因为高血压，我爸一直吃药」 | 爸爸漏抽 | 原因状语前置时，主语在后段被判为不相关 |

两套独立留出集互相印证：**F1 稳定在 0.87 左右**（0.877 / 0.868），开发集的 1.000 不具参考价值。

### 词表缺口已系统补齐（`docs/lexicon-gaps.md`，自动统计 185 条输入）

补齐：老爷子、二舅/三舅、三姑、血压偏高、贫血、骨质疏松、甲状腺结节、结石、胃病，
并补「裸我」识别（「我四十岁做过心脏支架」此前完全识别不到本人）。
补齐后缺口只剩 **舅妈**（姻亲）与 **太奶奶**（曾祖辈）——这两个故意不收：产品不支持该关系，
硬映射会造成误判。

### holdout-v3 的 7 条失败：瓶颈已经从词表转到模型

| 例 | 现象 | 真因 |
|---|---|---|
| 「我妈甲状腺结节」「我妈骨质疏松」「姥姥心脏不好」 | 漏抽 | 词表已收录，但**模型直接返回空**，规则层无法凭空造病 |
| 「我爸做过心脏手术，具体什么病不清楚」 | 漏抽 | 「心脏手术」不是别名；模型也没归到 other |
| 「我妈是不是有高血压啊？」 | 漏抽 | 疑问句，few-shot 里没有这种句式 |
| 「我大伯四十八岁做的支架」 | 漏抽 | 「做支架」未进 verbAliases |
| 「我舅公高血压」 | 误抽 maternal-uncle | 「舅公」被「舅」前缀命中（边界集合未含「公」）|

前 4 类是**模型召回问题**，不是规则问题：继续加别名不会让模型输出它认为「不是病」的东西。

### 三轮的真实轨迹（这才是重点）

| 轮次 | 开发集 | 当时的留出集 | 说明 |
|---|---|---|---|
| 起始 | — | 0.867 | 未修补 |
| 修 5 类失败后 | 0.971 | **0.955** | 提升真实有效 |
| 再修 4 类 + 关系接地后 | 1.000 | **0.877** | **开发集涨到 1.000，留出集反而掉了** |

第二轮掉分的原因是新加的「关系必须有原文依据」规则：它在开发集上消掉了 1 个误抽，
却在没见过的措辞上误杀了召回——**开发集涨、留出集跌，就是过拟合的典型信号**。

|---|---|---|

## 三、判定层（遗传模式）的准确性

同一批均衡样本（每类 5 条）配对比较，产物 `ml/out/inheritance_eval.json`：

| 后端 | 准确率 | ECE | 单次延迟 |
|---|---|---|---|
| OpenJev-Q4（18.5 GB） | 40% | 0.401 | 6.3 s |
| 结构逻辑回归（12 维，2.3 KB） | 96% | — | <0.1 s |

**边界**：96% 是合成集上的同分布成绩（训练与测试同源于 `ml/gen_inheritance_eval.py`），
不等于真实家系准确率。真实数据需要医生复核才有意义——没有就不宣称。

## 四、当前已知失败模式（来自口语 v2 产物，14/80 不完全匹配）

已修（对应 `src/lib/extract/repair.ts` 与 `splitSegments` 的两处改动）：

| 类型 | 修法 |
|---|---|
| 称谓混淆（我哥→paternal-uncle、爸→paternal-uncle） | 文中称谓词做确定性重映射，模型关系若在文中无依据就用剩余称谓补 |
| 续句主语丢失（「我妈高血压，我哥也是」） | 识别续句 → 补上一句病名 → 再送模型 |
| 病种回退 other（房颤/慢阻肺/老年痴呆） | 原文命中词表别名就换回真编码；既无别名又无疾病信号才丢 |
| 口语动词误判（「一直在吃药」→other） | 同上：无别名无信号直接丢 |
| **整句消失**（「姑姑有甲状腺问题」切出空数组） | `splitSegments` 不再丢弃「有称谓但无词表病名」的片段 |

仍有 4 条失败（76/80）：

| 例 | 现象 | 推断原因 |
|---|---|---|
| 「爷爷糖尿病，爸爸高血压」 | 高血压挂到爷爷 | 主语前缀跨句携带时张冠李戴 |
| 「外婆高血压，妈妈也是」 | 妈妈漏抽 | 中间续句的继承链断在第二跳 |
| 「…爷爷好像也是」 | 爷爷漏抽 | 「好像」被不确定性过滤挡掉 |
| 「我爸高血压，对，就是高血压」 | 多出一个 paternal-uncle | 改口句被切成两段后重复归属 |

下一轮修这四条，重跑并新增产物文件，**不覆盖旧文件**。

## 五、做不到的（诚实边界）

1. **没有临床验证**：无医生复核、无真实患者随访，所有指标都是工程评测。
2. **没有用户数据回流**：隐私优先，不做埋点式准确率统计。
3. **抽取评测集是自建的**：分布比真实口述窄，指标偏乐观。
4. **合成集只证明「结构可判」**，不证明「真实家系可判」。

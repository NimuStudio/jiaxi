# 演示视频脚本（8 分钟）

> 要求：MP4 / ≥1080p / 普通话讲解 / 可配字幕
> 建议：录屏 1920×1080，浏览器缩放 100%，深色桌面背景衬托浅色界面

---

## 录前准备

```bash
# 1. 启动推理服务
llama-server -m <模型路径>/qwen3-1.7b-q4_k_m.gguf -ngl 99 -c 4096 --port 8080

# 2. 启动前端（生产模式更稳，无 dev 浮层）
pnpm build && pnpm start        # http://localhost:5173

# 3. 浏览器开三个标签，按顺序切换
#    /chat          对话 + 家系图
#    /chat?demo=1   预置家系（备用，防止现场抽错）
#    /              风险量化 + 行动方案 + 依据
```

**录音注意**：先录屏、后配音，不要现场边操作边说话（容易卡）。

你爸 52 岁放的支架。

体检报告写着「未见异常」。

**旁白**
> 你爸 52 岁放的支架。你今年 31 岁。体检报告写着未见异常。
>
> 这句话的问题不在「未见异常」，在于**没人问过你爸几岁放的支架**。

**字幕**
`没人问过你爸几岁放的支架`

## 0:35–1:30　问题

**画面**
分屏对比：

| 左：线下问卷 | 右：真实信息 |
|---|---|
| 家族史：□ 有　□ 无 | 父亲 52 岁心梗、爷爷 62 岁糖尿病、外婆 68 岁脑卒中 |

**旁白**
> 家族史这三个字，几乎所有健康问卷都会问。但它只让你勾一个「有 / 无」。
>
> 而真正决定临床意义的，是另外三个量：**是谁**（一级亲属还是二级亲属）、**几岁发病**、**几个亲属**。
>
> 同一个「父亲有心脏病」——52 岁发病和 72 岁发病，结论是反的。52 岁属于早发家族史，要提前筛查；72 岁属于常见事件，参考价值大幅下降。
>
> 问卷把这三个维度全扔了。而家系图这个工具，在临床上用了一甲子，医生画在病历本上，患者一辈子见不到第二次。

**字幕**
`价值不在「有没有」，在「谁 / 几岁 / 几个」`

## 1:30–3:50　主演示：说出来，图就长出来

**画面**
`/chat` 页面。左侧聊天框，右侧空白家系图。

依次输入（每句间隔 3–5 秒，让动画走完）：

1. `我爸 52 岁那年放了心脏支架`
2. `我爷爷糖尿病，好多年了`
3. `外婆和姨妈都有乳腺癌，姨妈 48 岁查出来的`
4. `我舅舅 45 岁查出糖尿病，我妈身体还行`

每句发送后，右侧图上长出对应节点。

**旁白**（配合画面节奏）
> 左边用大白话说，右边这张图会自己长出来。
>
> 「我爸 52 岁那年放了心脏支架」——父亲这个位置，出现一个方形节点，实心表示有病。方形是男性，圆形是女性，这是临床家系图的通用画法，医生一眼能看懂。
>
> 「我爷爷糖尿病」——父系祖辈，加到上一代。
>
> 「外婆和姨妈都有乳腺癌，姨妈 48 岁查出来的」——注意这句里是**两个人**，模型要把她们拆开，各自归位。
>
> 「我舅舅 45 岁查出糖尿病，我妈身体还行」——最后半句是干扰，「身体还行」不算患病，不能抽进来。
>
> 信息可以想到哪说到哪，不用按顺序，图上会持续补充。

**画面**（3:20 处）
点一下「父亲」节点，弹出证据面板：

```
父亲 · 心梗
依据
「我爸 52 岁那年放了心脏支架」
[ 这条不对，删掉 ]
```

**旁白**
> 每个节点都能点开。这是它从你哪句话抽出来的，一字不差。抽错了，直接删掉。
>
> 模型说的话，必须是**可见、可改、可追溯**的。

**字幕**
`每个节点都能点回原话`

## 3:50–4:50　风险拆解：这 0.9 是你的

**画面**
切到 `/`。界面显示：

```
33%   高     FINDRISC 总分 16 分 · 高风险区间为 15–20 分
33% 现在  —— 7 分可回收 ——  4% 全部达标后
```

拖 BMI 滑块从 27 到 24.5，数字跳变；再拖腰围。

**旁白**
> 图上这些信息，会直接喂给风险计算。家族史这一项，在 FINDRISC 里权重最高：一级亲属患病记 5 分，二级亲属记 3 分。这个 5 分不用你回答，是从图上数出来的。
>
> 现在总分 16，落在高风险档，这一档对应的十年风险大约是三成。
>
> 但这里有个区别，是这套产品的核心：**风险里有一部分是改不了的，有一部分是能拿回来的**。
>
> 年龄、家族史、既往血糖史，改不了。BMI、腰围、体力活动、蔬果摄入，能改。把这四项全部做到 0 分，总分下降 7 分——**这就是可回收的风险**。
>
> 你拖一下试试：BMI 降到 24.9，分数立刻掉。33% 变成 4%。
>
> 这就是为什么我们不说「注意身体」，因为那句话没法验证。这个数字可以。

**字幕**
`33% → 4%，中间 7 分是你的`

## 4:50–5:50　技术：模型在外，规则在内

**画面**
架构图（静态图或手绘动画）：

```
浏览器 → Next.js → 本地 llama-server (Qwen3-1.7B)
                      ↑ GBNF 约束解码
        ↓
   词表校正 → 证据校验 → 合并去重
```

**旁白**
> 技术上最关键的一个选择：**整个链路跑在本地**。家族病史是最敏感的信息之一，它一次都没有离开这台电脑。
>
> 模型用的是 Qwen3-1.7B，量化后 1.2G，单次抽取一到两秒。它不算聪明，所以我们不让它做判断。
>
> 第一层，**约束解码**。输出格式不是靠提示词祈祷，是在解码层用文法锁死，吐出来的东西一定是合法 JSON。
>
> 但格式对不等于内容对。所以外面还有三层：
>
> 一是**词表校正**——模型会把「老爹」认成伯叔，但文本里明明写了称谓，这时以词表为准。
>
> 二是**证据校验**——每个抽出来的病，必须在你原话里找得到，找不到就删掉。这一条把口语集的精确率拉到了 1.000：**抽出来的每个病都有原文依据，一个编造的都没有**。
>
> 代价是召回率降低，有些说法词表没覆盖就被删了。这个交换在医疗场景是必须的：**宁可漏，不可编**。
>
> 三是去重和合并，同一人说了两遍不会变成两个节点。

**字幕**
`约束解码管格式，三层校验管内容`
`口语集精确率 1.000`

## 5:50–6:50　这周做什么 + 依据

**画面**
向下滚动到「这周做什么」：

```
不要求你全改。只挑两件性价比最高的：做完能拿回 5 分。

① 每天活动到 30 分钟          +2 分
   这周：先从每天 10 分钟开始，一周后加到 15 分钟
② 把腰围从 96 cm 降到 90 cm 以下   +3 分
   这周：饭后走 15 分钟，比节食更容易坚持

＋ 还有 2 项，等这两件稳住了再说
```

再滚到「这些数字凭什么」，点击预设问题「为什么家族史这么重要」，展示检索结果与出处。

**旁白**
> 知道该改什么，不等于会改。所以这里不列八条建议让人全做，而是按性价比排序，只留两件这周能做的。
>
> 每条都必须有一个今晚就能做的动作。「多运动」不会让人动，「先从每天 10 分钟开始」才会。
>
> 剩下的折叠起来，不假装要求你全改。
>
> 最后，任何一个数字都可以问「凭什么」。答案来自已核实的文献，每条带出处。**找不到就直说找不到**——我们宁可承认不知道，也不让模型编一段听起来很专业的话。

**字幕**
`只给两件，每件有最小动作`
`查不到就说查不到`

## 6:50–7:30　验证：两组数字

**画面**
评测结果表格：

| 评测集 | Precision | Recall | F1 |
|---|---|---|---|
| 规整句 16 条 | 0.952 | 0.952 | 0.952 |
| 口语 21 条 | **1.000** | 0.714 | 0.833 |

**旁白**
> 我们自己建了两套评测集。
>
> 一开始只有一个规整句的评测集，F1 是 0.93。但我们意识到这些句子是自己编的，太书面了。于是又建了一套刻意口语化的，同样一套模型，**F1 掉到 0.61**。
>
> 这个 0.61 才是真实水平。承认它，然后才有后面的修复：分句、词表、证据校验。
>
> 现在口语集精确率是 1.000，召回率 0.71。差的那部分是词表覆盖，还在补。

**字幕**
`口语集 0.61 → 0.833，精确率 1.000`

## 录制检查清单

- [ ] 1080p 以上，画面不糊
- [ ] 旁白语速：每秒约 4 字，全程不赶
- [ ] 每处数字与界面对得上（33% / 4% / 7 分 / 16 分）
- [ ] 家系图动画完整播放，不要剪太快
- [ ] 证据面板、行动方案、依据检索三处都要出镜
- [ ] 全程无报错浮层、无 502、无浏览器扩展图标
- [ ] 结尾停在「52 是有意义的」这句，不要拖

## 备用方案

若现场抽取出现偏差（模型有随机性）：

1. 不要重录整段，直接在图上**点开节点删掉**——这本身就是产品能力，反而说明「抽错可以改」
2. 或切到 `/chat?demo=1` 的预置数据继续

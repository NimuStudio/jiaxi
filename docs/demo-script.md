# 演示视频脚本（7 分 15 秒）

> 要求：MP4 / ≥1080p / 普通话讲解 / 可配字幕
>
> **制作方式：动画段 + 录屏段混合。**
> 动画段用 Remotion 生成（确定性、可重渲染、改一次文案重出一次片），
> 录屏段展示真实系统在跑。
>
> 为什么不全用动画：评分表里「AI 技术亮点展示」要看到系统真在跑，
> 纯动画会被当成 PPT。
> 为什么不全用录屏：开场、技术链路、风险尺收缩这几屏，
> 录屏做不出稳定的运镜和节奏，而且一改文案就得重录。

---

## 一、成片结构

| # | 时间 | 类型 | 内容 | 素材 |
|---|---|---|---|---|
| 1 | 0:00–0:38 | 动画 | 冷开场：一句家族史 → 家系图长出 → 片名 | `out/1-opening.mp4` |
| 2 | 0:38–3:00 | 录屏 | 主演示：对话录入、图实时生长、点节点看依据 | 浏览器 `/chat` |
| 3 | 3:00–4:02 | 动画 | AI 链路：分句 → 约束解码 → 词表校正 → 证据校验 | `out/2-pipeline.mp4` |
| 4 | 4:02–4:52 | 动画 | 可回收风险：33% → 17% → 4%，橙色段被吃掉 | `out/3-riskdrop.mp4` |
| 5 | 4:52–5:50 | 录屏 | 行动方案、依据检索、三样输出物 | 浏览器 `/` |
| 6 | 5:50–6:40 | 录屏 | 验证：评测集复跑、生产构建、本地推理 | 终端 + 浏览器 |
| 7 | 6:40–7:00 | 动画 | 收尾：三样交付物 + 「使用者与受益者是两个人」 | `out/4-outro.mp4` |
| 8 | 7:00–7:15 | 录屏/字卡 | 在线地址 + 结束 | 字卡 |

**动画段合计 2:50，录屏段合计 4:10。** AI 深度那 35% 的展示落在第 3 段和第 6 段，共 1 分 50 秒。

## 二、渲染动画段

```bash
cd video
pnpm install                 # 首次
npx remotion studio          # 打开预览，可逐帧调整

# 出片（四段分开渲染，方便剪辑时插录屏）
npx remotion render src/index.ts Opening  out/1-opening.mp4  --codec=h264 --crf=18
npx remotion render src/index.ts Pipeline out/2-pipeline.mp4 --codec=h264 --crf=18
npx remotion render src/index.ts RiskDrop out/3-riskdrop.mp4 --codec=h264 --crf=18
npx remotion render src/index.ts Outro    out/4-outro.mp4    --codec=h264 --crf=18
```

浏览器用的是本机 Edge（见 `remotion.config.ts`），因为这台机器访问不到
`storage.googleapis.com`，Remotion 无法自动下载 Chrome Headless Shell。

**动画里出现的每个数字都来自代码的真实计算**，不是写死的：
- 33% / 4% / 7 分 / 16 分 → `src/lib/risk/findrisc.ts` 的实际输出
- F1 0.952 / Precision 1.000 → 评测脚本的实际结果
- 所以改代码后重渲染，画面会跟着变，不会出现「视频说 33%、产品说 17%」。

## 三、录前准备

```bash
# 1. 推理服务（本地，家族病史不出机器）
llama-server -m <模型路径>/qwen3-1.7b-q4_k_m.gguf -ngl 99 -c 4096 --port 8080

# 2. 前端（生产模式更稳，无 dev 浮层）
pnpm build && pnpm start        # http://localhost:5173
```

浏览器开三个标签：

| 标签 | 地址 | 用途 |
|---|---|---|
| A | `/chat` | 真实录入 |
| B | `/chat?demo=1` | 备用：预置家系，防止抽取翻车 |
| C | `/` | 风险量化 + 行动方案 + 依据 |

**录音顺序：先录屏、后配音。** 边操作边说容易卡壳，而且重录一次要重做全部操作。

## 四、逐段脚本

### 1　0:00–0:38　冷开场（动画，无需录屏）

播放 `1-opening.mp4`。画面自带字幕，**这一段不要配旁白**，让它安静地走完。
第 33 秒片名「家系」出现时，再进第一句旁白。

> 旁白（0:33 起）：
> 「家族史是筛查指南里权重最高的信息之一。但今天，它被压缩成了一个勾选框——有，还是没有。」

---

### 2　0:38–3:00　主演示：说出来，图就长出来

**画面**：标签 A，`/chat`

| 操作 | 说明 |
|---|---|
| 输入「我爸五十二岁那年放了心脏支架」 | 停顿 2 秒，等节点长出（动画约 200ms，但要让观众看清） |
| 输入「我舅舅四十五岁查出糖尿病，外婆是肺癌走的」 | 一句话两个人，展示分句生效 |
| 输入「我妈身体还行」 | 展示否定句被正确排除，图上不多出节点 |
| 点「父亲」节点 | 展开证据面板：「依据：我爸五十二岁那年放了心脏支架」 |
| 点「这条不对，删掉」再撤回 | 展示抽错时用户能自己纠正（**这段要留**，它证明产品不是黑盒） |

> 旁白：
> 「说的是人话，出来的是一张图。每说一句，图上就多一个人；
> 说他几岁发病，节点上就带上年龄。
> 点开任何一个节点，都能看到它是从哪句话抽出来的——抽取结果在图上可见、可改。
> 这不是一个『模型说什么就是什么』的东西。」

---

### 3　3:00–4:02　AI 链路（动画）

播放 `2-pipeline.mp4`。**这一段是全片技术含量最高的地方，不要压旁白盖住画面**，
只在每个环节切换时说一句。

> 旁白（跟着画面走）：
> 「一句话要变成图上的人，中间有五步。
> 第一步分句——一点七 B 的模型在长句里会漏掉第二个人，所以每次只让它面对一个亲属。
> 第二步约束解码——格式在解码层就被锁死，它不可能输出非法结构。
> 第三步词表校正——『舅舅』曾被稳定抽成 brother，把二级亲属错认成一级；
> 现在句中只出现唯一称谓时，以词表为准覆盖模型判断。
> 第四步证据校验——原文没提到的病，一律删掉。
> 加上这条硬规则之后，口语测试集上精确率是一点零零零：抽出来的每个病，都能在原话里找到。」

---

### 4　4:02–4:52　可回收风险（动画）

播放 `3-riskdrop.mp4`。

> 旁白（0:00–0:20，跟着 33% 出现）：
> 「十六分，未来十年风险百分之三十三。
> 但这里面有七分，是他自己能拿回来的：体质指数、腰围、每周活动、每天蔬果。」

> 旁白（0:20–0:43，跟着橙色段收缩）：
> 「腰围降到八十八，三分拿回来了；每周活动起来，又是两分。
> 三段橙色被一段一段吃掉，风险从三十三掉到十七，再掉到四。」

> 旁白（0:43–0:50，画面停在 4%）：
> 「这中间没有一句『你要注意身体』。只有一个他自己拖得动的数字。」

### 5　4:52–5:50　行动方案与依据

**画面**：标签 C，`/`

| 操作 | 说明 |
|---|---|
| 从上往下滚一遍 | 让观众看到「可回收 7 分」和风险尺 |
| 拖 BMI 滑块 | 数字实时跳，展示反事实是即时算的 |
| 滚到「这周做什么」 | 两条建议，各带最小动作 |
| 展开「还有 2 项」 | 展示不假装要求全改 |
| 在依据框输入「为什么家族史重要」 | 返回条目 + 出处 |
| 再输入「今天天气怎么样」 | **返回「没找到」**——这一段要留，它证明不硬凑答案 |

> 旁白：
> 「它不会给你八条建议让你全做。按『效果除以难度』排序，只留两件这周能做的，
> 每件都带一个今晚就能动的动作。
> 剩下的折叠在那里——不假装要求你一次全改。
> 任何一个数字你都可以问『凭什么』。查得到就给原文，查不到就说没有。」

### 6　5:50–6:40　验证

**画面**：终端 + 浏览器

| 操作 | 说明 |
|---|---|
| `pnpm test` | 23 个用例全绿 |
| `node scripts/eval-extract.ts` | 规整集 F1 0.952 逐条打印 |

> 旁白：
> 「两组数字。规整句子 F1 零点九五二；真实口语下精确率一点零零零，召回零点七五零。
> 精确率优先是刻意的：在这个场景里，漏掉一个亲属只是信息不全，
> 编造一个病会让下游给出错误的筛查建议。宁可漏，不可编。
> 另外，整个抽取跑在本机——家族病史一次都没有离开这台电脑。」

## 五、剪辑要点

- **动画段与录屏段的转场用硬切**，不要加花哨转场。这类作品的可信度来自克制。
- 录屏段统一 1920×1080，浏览器缩放 100%，隐藏书签栏。
- 动画段已有字幕，录屏段建议整体压一层字幕条，两边风格统一。
- 配乐只在动画段铺，音量 −26 dB 左右；录屏段留白，让人听清操作反馈。

## 七、抽取翻车了怎么办

**不要重录。** 直接点开抽错的节点，点「这条不对，删掉」，或者重新说一遍。

这个动作本身就是产品能力的一部分——**抽取结果可见、可改**。
真在录屏里出现一次纠正，比全程顺利更能说明问题。

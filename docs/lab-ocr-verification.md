# 化验单 OCR 技术验证（2026-11-05）

> 目的：判断「拍照上传化验单 → 自动填体检数字」这条路能不能做，用实测数据决定，而不是凭感觉。

> **状态：已实现**（2026-11-05）。实现见下方「落地形态」一节。

## 结论

| 方案 | 干净图 | 退化图（旋转 3.5°+缩放 72%+JPEG） | 耗时 | 可用性 |
| --- | --- | --- | --- | --- |
| **tesseract.js（纯前端）** | 数值 **0/6 正确** | 更差（整行丢失） | 107 / 114 秒 | ❌ 不可用 |
| **Qwen2.5-VL-3B Q4 + mmproj（本地 llama.cpp）** | **6/6** | **6/6** | 17 / 14 秒 | ✅ 可用 |

**tesseract 的致命问题不是"识别率低"，而是小数点丢失**：

```
糖化血红蛋白 6.4 %   →  识别为  "糖化 血红 蛋白 64 %"
总胆固醇 5.72        →  识别为  "总 胆 国 醇 572"
空腹血糖 6.8         →  （退化图上整行变成 "ma so"）
```

6.4 变 64、5.72 变 572 —— 在医疗场景里这是**量级错误**，比"没识别出来"危险得多。
再叠加 100 秒以上的耗时，前端方案直接排除。

VLM 方案在退化图上仍然 6/6，包括小数点、单位与参考范围。

## 若要落地，成本与设计约束

**成本**：额外 2.6 GB 模型（`ml/vlm/model.gguf` 1.80 GB + `mmproj.gguf` 0.79 GB），
以及**第二个 llama-server 进程**（8082 端口，`--mmproj`）——演示机要多常驻一个模型。
`start-demo.cmd` 需要加一段，评审期多一个可能挂掉的组件。

**设计约束（安全优先）**：
1. 识别结果**不得直接写入**体检数字，必须逐项展示给用户确认后才填（`RiskFactorsForm`）；
2. 只接受"项目名 + 数值"，参考范围与箭头仅作对照展示，不参与计算；
3. 识别失败或字段缺失时，保持原有手动输入路径，不阻塞；
4. 上传的图片默认不留存（内存处理，不落盘、不入库）。

## 复现

```bash
# 视觉模型（已下载到 ml/vlm/）
llama-server -m ml/vlm/model.gguf --mmproj ml/vlm/mmproj.gguf -ngl 99 -c 4096 --port 8082

node _ocr_verify/vlm-test.mjs _ocr_verify/report.png            # 干净图
node _ocr_verify/vlm-test.mjs _ocr_verify/report-photo.jpg      # 退化图
node _ocr_verify/tess/run.cjs _ocr_verify/report.png            # tesseract 对照
```

## 落地形态（已实现）

| 部分 | 位置 | 说明 |
| --- | --- | --- |
| 纯函数层 | `src/lib/ocr/parse.ts` | 解析模型输出、清洗数值、映射到 China-PAR 字段、mg/dL→mmol/L 换算。规则与模型分离：数值映射错了会算错风险，这一步不交给模型 |
| 接口 | `app/api/ocr/route.ts` | GET 探可用性；POST 收 base64 图片 → 本机视觉模型 → 返回 `{items, fields, unused}`。图片不落盘不入库，8 MB 上限，90 秒超时 |
| 界面 | `src/components/cvd/LabReportImport.tsx` | 视觉模型不在线时**整个入口不渲染**；识别结果逐项勾选 + 「确认填入」后才写表单 |
| 演示脚本 | `scripts/start-demo.cmd` 第 3/5 步 | 有模型文件才启动 8082；缺文件则跳过并提示「化验单入口会自动隐藏」 |
| 环境变量 | `.env.example` 的 `VLM_SERVER_URL` | 默认 http://127.0.0.1:8082 |

**只映射化验单上真能读到的字段**：年龄、收缩压、总胆固醇、高密度脂蛋白。
血糖/糖化血红蛋白**不**映射成「已诊断糖尿病」——「血糖偏高」不等于「糖尿病」，
错用会改变 China-PAR 结果。识别到但本页用不上的项目会以 `unused` 返回，界面如实说明。

实测（端到端，经站点）：上传 900×420 化验单 → 9.5 秒返回，映射出总胆固醇 5.72、高密度脂蛋白 1.02，
甘油三酯 2.15 正确落到 `unused` 而不是硬塞进别的字段；停掉 8082 后入口消失、接口返回 503。

## 建议

技术上可行，但**这是一次产品决策，不只是技术决策**：
多常驻一个 2.6 GB 模型换来"拍照填数字"，收益是省用户手动输入 6 个数字；
成本是演示机多一个组件、评审期多一个故障点。

如果做，我建议按上面的安全约束实现，并且**只在检测到 VLM 服务在线时显示入口**，
离线时入口隐藏——和语音识别按钮的处理方式一致。

# 家系 · 准确性说明

> 面向评审：每一句话都有对应命令与产物文件支撑，结论可复算。
> 数据与误差都如实列出，包括我们做失败的一条路线（微调）。

## 一、一句话

**口语化家族史的信息抽取，在 5 套"全新措辞、只跑一次"的留出集上，
当前成绩为 Precision 1.000 / Recall 0.966 / F1 0.982 / 年龄准确率 0.964。**
所有数字来自规则层与词表，未使用微调模型（微调做过并被数据否掉，见第五节）。

## 二、准确性靠什么保证：三层分离

| 层 | 内容 | 保证手段 | 是否依赖模型 |
|---|---|---|---|
| ① 确定性计算 | FINDRISC / China-PAR / PLCO2012 风险值 | 对齐原始论文公式；边界值、NaN、缺项均有用例；`sanitize()` 兜底 | 否 |
| ② 抽取 | 口述病史 → 结构化 JSON | 人工标注 + 5 套留出集 + 每次改动跑回归 + 精确率优先 | 是，但有评测与规则兜底 |
| ③ 判定 | 遗传模式 | 配对评测 + 校准 ECE + 置信度门槛 + 拒答 | 是，可换后端对比 |
| ④ 展示 | 用户看到的结论 | 不确定就不显示；文案写「提示，不是诊断」；缺口用于追问 | 否 |

**设计原则**：模型只做它不可替代的事——把口语变成结构。凡涉及判断，先问能否用规则或
可复算的方式做；不能才交给模型，且必须给出置信度与拒答路径。

## 三、评测方法：留出集制度

这是本文最应该被检验的部分，因为它决定数字是否可信。

1. **每套留出集都是全新措辞，只跑一次**。跑过即降级为开发集，不再用于对外报数。
2. **每次评测自动留痕**：`docs/eval-results/<时间>-<集名>.json` 记录 commit、模型路径、
   是否 few-shot、逐条预测与 TP/FP/FN。
3. **指标定义**：把"人 × 病"展开成 `(relation, code)` 对，与人工标注比对，
   算 Precision / Recall / F1；年龄单独统计（容差 ±2 岁）；完全匹配要求整条输入全部正确。
4. **规则调优不得回头改留出集**。开发集涨、留出集跌，一律视为过拟合信号并记录。

### 留出集的渐进过程（每套只跑一次）

| 留出集 | 期间做了什么 | Precision | Recall | F1 | 完全匹配 |
|---|---|---|---|---|---|
| v2 | 规则修补（称谓/续句/病种回退） | 0.962 | 0.806 | 0.877 | 23/30 |
| v3 | 按词表缺口清单系统补齐 | 0.958 | 0.793 | 0.868 | 23/30 |
| v5 | 规则抽取兜底 + few-shot 补模糊病名 | 1.000 | 0.839 | 0.912 | 25/30 |
| v7 | 支架/血压变体、续句用原话、状语前置、疑问句非否定 | 1.000 | 0.933 | 0.966 | 28/30 |
| **v8** | 血糖/心脏别名变体 | **1.000** | **0.966** | **0.982** | **29/30** |

> 中途出现过一次典型的过拟合：某轮改动让开发集从 0.971 涨到 1.000，留出集却从 0.955 掉到 0.877。
> 我们把这次回落如实记录，并回退了那条过激规则（"关系必须有原文依据"改为更保守的版本）。

## 四、当前失败分析

v8 唯一失败：「我叔做过两次支架」——别名收录的是「做支架」，匹配不到「做过两次支架」。
再往下修需要把裸「支架」入表，代价是可能误命中其他语境，因此暂不修，继续观察。

历史失败模式的归纳（均已修，可作为方法论参考）：

| 类型 | 例子 | 修法 |
|---|---|---|
| 称谓错配 | 「我哥」被抽成 paternal-uncle | 文中称谓词做确定性重映射 |
| 续句主语丢失 | 「我妈高血压，我哥也是」 | 识别续句 → 补上一句病名原话 |
| 病种回退 other | 房颤/慢阻肺/老年痴呆 → other | 原文命中别名则换回真编码 |
| 整句消失 | 「姑姑有甲状腺问题」切出空数组 | 切句不再丢弃"有称谓无词表病名"的片段 |
| 多病错挂 | 「爷爷糖尿病，爸爸高血压」 | 修正切句的主语归属规则 |
| 模糊病名漏抽 | 甲状腺结节/骨质疏松 | 模型返回空时用规则兜底抽取 |

## 五、做过但否掉的路线：微调

我们完整做过一次微调，并在**从未参与训练**的封存集（v6，30 条）上做 A/B：

| 配置 | Precision | Recall | F1 | 完全匹配 |
|---|---|---|---|---|
| 基线（基座 + few-shot + 规则层） | 1.000 | 0.893 | 0.943 | 27/30 |
| 微调（无 few-shot + 规则层） | 1.000 | 0.893 | 0.943 | 27/30 |
| 基线模型原始能力（跳过规则层） | 0.957 | 0.786 | 0.863 | 23/30 |
| 微调模型原始能力（跳过规则层） | 0.957 | 0.786 | 0.863 | 23/30 |

逐条比对 30 条输出：模型层仅 2 条不同、指标完全一致；叠加规则层后 30/30 完全相同。

**结论：本任务上微调无可测增益**。原因是输出空间被 GBNF 约束 + 词表 + few-shot 收得很窄，
基座模型已能做对，微调学到的是 few-shot 里已经写明的东西。
**处置：不引入微调模型**，省下 1.1 GB 权重与一套维护负担。

训练链路本身是通的（1355 条数据、3 epoch、21 分钟、merge → GGUF → Q4_K_M），随时可复验。

## 六、不做与做不到的

1. **没有临床验证**：无医生复核、无真实患者随访，所有指标都是工程评测。
2. **没有用户数据回流**：隐私优先，不做埋点式准确率统计。
3. **抽取评测集是自建的**：分布比真实口述窄，指标偏乐观；这也是我们坚持"留出集只跑一次"的原因。
4. **遗传模式的结构模型 96% 是合成集同分布成绩**（训练与测试同一生成器），
   不等于真实家系准确率，文档中已单独标注。
5. **不宣称诊断**：产品文案统一写「模型提示，不是诊断」。
